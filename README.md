# Operator Data Model

A vendor-neutral data model for building operations, based on Linked Data. Not another standard and not a new data structure, but the connection of existing standards and domains through defined integration points.

## Approach

We are not building a new ontology and not a replacement for existing standards. We are building an integration layer that links established domain ontologies through defined and versioned integration points, following the principle "reference instead of copy". Each domain stays anchored in its own standard. The Operator Data Model provides the translation and linking rules between them and does not merge them into a new ontology.

## Standards and ontologies

* IFC — Industry Foundation Classes
* BOT — Building Topology Ontology
* Brick — Brick Schema
* ASHRAE 223P / 231P
* AAS — Asset Administration Shell
* IBPDI — International Building Performance & Data Initiative
* REC — RealEstateCore
* WoT — Web of Things (Thing Description)
* DBL — EU Digital Building Logbook
* Haystack
* SAREF

Together with the relevant protocols such as BACnet, MQTT, OPC UA, Modbus, KNX and LoRaWAN.

## Related work

The integration approach described here is being developed further under [Building Ontology Link](https://github.com/hsmainz-smart-building-reallabor/Building-Ontology-Link), the linking layer that defines the integration points between the domain ontologies listed above. This repository covers the operational scope of that layer, the model for building operations.
